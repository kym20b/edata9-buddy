# W5-목 기준 — 구조와 계보 (상담 만족도)

체크아웃 캡처: `erd.html` 그림 + 앱의 «상담 만족도» 카드와 계보 탭 + 6절의 점검 답 + 8절의 새 대화 답

## 점검 항목

| 항목 | 통과 조건 |
|---|---|
| ERD | `edata9-work/metric-dictionary/erd.html` 이 있고 `erDiagram` 이 들어 있다 |
| 상담 만족도 정의서 | `metrics/상담_만족도.json` 이 있고 `metrics/index.json` 에 이름이 있다 |
| 문장과 SQL | `상담_만족도.json` 의 `sql` 이 `agents` 를 조인하고(`JOIN agents`) `sources` 에 `agents.is_resigned` 가 있다 — 이름이 달라도 같은 역할이면 통과 |
| 점검 스킬 | `metric-dictionary/.claude/skills/정의점검/SKILL.md` 가 있고 `disable-model-invocation` 이 들어 있다 |
| 카드 · 계보 · 새 대화의 답 | 앱 화면과 대화는 «확인 불가 — 캡처로 확인» |

## 미흡일 때

- `erd.html`이 없다 → 교안 3절 프롬프트(Mermaid를 `erd.html` 하나로 저장)
- 정의서가 없다 → 교안 5절 프롬프트. 파일 이름은 `상담_만족도.json`. 정의서 id는 Claude가 붙여 실행마다 다르므로 검사하지 않는다
- 문장은 바뀌었는데 `sql`이 그대로다 → 교안 6절의 점검 뒤 «SQL을 고쳐줘» 프롬프트. 앱은 `sql`만 읽으므로 문장만 고치면 카드가 그대로다
- 스킬이 없다 → 교안 7절 `skill-creator` 프롬프트. «평가는 하지 말고 초안 하나만»을 넣는다
