# W6-토 기준 — 도메인 실험 데이터로: 판정기를 데이터만 바꿔 쓰고, 내 업무의 실험을 설계한다

체크아웃 캡처: 도메인 판정기의 다섯 판정 중 하나 + 노션 «실험 관리»의 판정 완료 행 + 내 가상 실험의 필요 기간

## 점검 항목

| 항목 | 통과 조건 |
|---|---|
| 도메인 데이터 | `edata9-work/domain-data/data/experiments.csv` · `data/experiment_assignments.csv` · `docs/데이터_사전_실험.md` 가 있다 |
| 판정기 사본 | `edata9-work/my-judge/` 에 `index.html` · `judge.js` · `rules.json` 이 있다 |
| 통신사 입력은 남겨 둠 | `my-judge/data/experiments_통신사.json` 이 있다 |
| 새 입력 파일 | `my-judge/data/experiments.json` 에 실험이 다섯 건 있고, 통신사 실험 id(`EXP-001` 등)가 남아 있지 않다 |
| 규칙 · 엔진 그대로 | `my-judge/rules.json` 의 `srm_p` 가 `0.001`, `mde_relative` 가 `10` 이다 — 오늘은 입력만 바꾼다 |
| 가드레일 방향 | 가드레일이 있는 실험에 방향(`better`)이 적혀 있다 — 낮을수록 좋은 가드레일이면 `lower` |
| 데이터를 배포 폴더에 섞지 않음 | `my-judge/` 안에 `experiment_assignments.csv` 가 없다 |
| 통계검산관(도전) | `my-judge/.claude/agents/통계검산관.md` 가 `domain-data` 의 CSV를 읽게 바뀌어 있다 |
| 다섯 판정 화면 · 노션 행 · 내 가상 실험 | 화면과 노션은 «확인 불가 — 캡처로 확인». 노션이 이어져 있으면 «실험 관리»에 상태 «판정 완료» 행과 «설계 중» 행이 있는지 읽기만 해서 본다 |

## 미흡일 때

- 도메인 데이터가 없다 → 교안 1단계. 두 zip을 `C:\edata9-work\domain-data` 에 함께 푼다. `data` 폴더가 두 겹이면 한 겹을 정리한다
- `my-judge` 가 없다 → 금요일의 `w6-ab-judge` 폴더를 복사해 이름을 `my-judge` 로 바꾼다. 금요일을 따라오지 못했으면 목업 zip을 `my-judge` 에 푼다
- `experiments.json` 에 통신사 실험이 남아 있다 → 교안 3단계 프롬프트. 지금 파일은 `experiments_통신사.json` 으로 이름을 바꿔 남긴다
- `rules.json` 이 바뀌었다 → «rules.json 을 금요일 값(srm_p 0.001 · mde_relative 10)으로 되돌려줘. 다른 곳은 고치지 마»
- 가드레일에 방향이 없다 → «experiments.json 의 가드레일에 방향(better)을 데이터 사전대로 넣어줘»
- CSV가 `my-judge` 안에 있다 → 그 파일을 지우고 `../domain-data` 를 읽게 한다. 배포 폴더에 원본 데이터가 섞인다
