# W3-목 기준 — 맡기고, 검수하고, 다시 돌릴 수 있게 남긴다

체크아웃 캡처: **새 대화**가 `정리/` 의 스크립트와 결정 기록만 읽고 다섯 숫자를 다시 낸 화면

## 점검 항목

| 항목 | 통과 조건 |
|---|---|
| 정리 스크립트 | `cleaner/정리/` 에 `.py` 파일이 하나 이상 있다 |
| 결정 기록 | `my-wiki/decisions/` 의 `d-*.md` 가운데 본문이나 파일 이름에 `상담원장` 또는 `종결` 이라는 **글자**가 들어 있는 파일이 하나 이상 있다. 글자가 있는지만 찾는다 — 결정의 상태(끝났는지 · 반영했는지)는 보지 않는다 |
| 정리본 | `cleaner/정리본/상담원장_정리.csv` 가 있다. 줄 수를 세어 근거에 적는다 (머리글 빼고 3만 2천 줄대면 통과 — 숫자가 조금 달라도 미흡으로 보지 않는다) |
| 저장 지점 | `cleaner` 가 git 저장소이고, `정리/` 의 스크립트가 든 커밋이 있다 |
| 원본은 그대로 | `messy/상담원장_2025.xlsx` 의 수정 시각이 `cleaner/정리본/상담원장_정리.csv` 보다 앞선다 |

## 미흡일 때

- 스크립트가 `cleaner/정리/` 에 없다 → 교안 9절. «네가 쓴 정리 스크립트를 이 폴더의 정리/정리_상담원장.py 로 옮겨줘»
- 상담원장의 결정 기록이 없다 → 교안 8절. Claude가 대신 정한 것 가운데 내가 다시 정한 것을 결정 기록으로
- 정리본이 없다 → 스크립트를 한 번 돌리게 한다. «정리/정리_상담원장.py 를 돌려줘»
- 저장 지점이 없다 → 교안 9절 끝. `/따라잡기 W3-목-9`

## 보지 않는 것

- 정리본의 숫자가 맞는지는 보지 않는다. 다섯 숫자는 교안 2절 · 11절의 답과 내가 맞춰 본다
- 정답 파일(`tools/answer/`)을 열지 않는다
