# W4-목 기준 — 15장 조인과 부풀려지는 숫자

체크아웃 캡처: 계획 모드의 계획(«조인 후 몇 행»이 숫자로) + 실행 결과의 행 수

## 점검 항목

| 항목 | 통과 조건 |
|---|---|
| 레퍼런스 문서 | `sql-window/docs/테이블_레퍼런스.md` 가 있고, 테이블마다 그레인(«그레인» 또는 «한 행»)과 쓰면 안 되는 컬럼(예: `is_active`)이 적혀 있다 |
| 조인 규칙 | `my-wiki/decisions/` 에 오늘 날짜쯤의 결정 기록이 있고, 본문에 `JOIN`(또는 «조인» · «붙이»)과, 카디널리티(«1:N» · «1:1» · «몇 대 몇») 또는 행 수(«행 수» · «줄 수»)가 있다 |
| INNER의 이유 | 그 기록에 `INNER` 가 있으면, 같은 줄이나 다음 줄에 «잃어도» 같은 이유가 있다 |
| 내 질문 | `sql-window/questions.json` 의 질문이 목업의 아홉 개보다 많고, 새 질문마다 `judge` 가 있고 `check` 가 둘이다 |
| 인사이트 리포트 | `sql-window/인사이트_목.md` 가 있다 |
| 계획 화면 | 확인 불가 — 캡처로 확인 |

## 미흡일 때

- 레퍼런스 문서가 없다 → 교안 3절의 `/데이터카드`를 다시 부른다(명령 파일이 옛 판이면 3절 프롬프트로 다시 저장). 견본은 `/따라잡기 W4-목-3`
- 결정 기록이 없다 → 책 15-10. 견본은 `/따라잡기 W4-목-4`
- INNER에 이유가 없다 → 15-4의 질문 «한쪽 테이블에만 있는 행을 잃어도 되는가?»
