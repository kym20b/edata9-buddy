# W4-수 기준 — 14장 SQL로 직접 묻는다 · MCP

체크아웃 캡처: `edata9-data` 로 답한 재문의율 표와 그 SQL + `DELETE` 가 막힌 답

## 점검 항목

| 항목 | 통과 조건 |
|---|---|
| MCP 연결 파일 | `sql-window/.mcp.json` 에 `edata9-data` 가 있다 |
| 서버는 읽기만 | `sql-window/tools/duckdb_mcp.py` 에 `read_only` 검사와 `MAX_ROWS` 가 그대로 있다 — 고쳐졌으면 미흡 |
| 데이터는 그대로 | `sql-window/data/` 의 parquet 이 12개다 |
| MCP 응답 · BigQuery | 확인 불가 — 캡처로 확인 |

## 미흡일 때

- 서버 파일이 고쳐졌다 → 되감기 또는 `/따라잡기 W4-수-4`. 서버를 고쳐 «쓰기»를 열지 않는다(14-7)
- 연결이 안 된다 → 14장 «막히면»의 `pip install mcp duckdb`
