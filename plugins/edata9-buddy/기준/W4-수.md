# W4-수 기준 — 재문의, 어디부터 손대나 · MCP

체크아웃 캡처: `edata9-data` 로 답한 «어디부터» 화면 + `DELETE` 가 막힌 답 + `인사이트_수.md`

## 점검 항목

| 항목 | 통과 조건 |
|---|---|
| MCP 연결 파일 | `sql-window/.mcp.json` 에 `edata9-data` 가 있다 |
| 서버는 읽기만 | `sql-window/tools/duckdb_mcp.py` 에 `read_only` 검사와 `MAX_ROWS = 20` 이 그대로 있다 — 고쳐졌으면 미흡 |
| 데이터는 그대로 | `sql-window/data/` 의 parquet 이 12개다 |
| 결정 기록 | `my-wiki/decisions/` 에 «재문의»가 든 결정 기록이 있다 (우선순위의 기준 — 비율 · 건수) |
| 인사이트 한 장 | `sql-window/인사이트_수.md` 가 있고 «검증한 것»이 있다 |
| MCP 응답 · BigQuery | 확인 불가 — 캡처로 확인 |

## 판정에 넣지 않고 알려 줄 것

- `인사이트_수.md` 나 결정 기록에 `7,426` 또는 `22.6%` 가 있으면 한 줄로 알린다 — 창에서 센 값은 7,427건 · 22.7%다(교안 5절)

## 미흡일 때

- 서버 파일이 고쳐졌다 → 되감기 또는 `/따라잡기 W4-수-3`. 서버를 고쳐 «쓰기»를 열지 않는다(교안 4절)
- 결정 기록이 없다 → 교안 6절 프롬프트. 번호는 내 위키의 다음 번호
- 연결이 안 된다 → 교안 «막히면»의 첫 줄(`mcp` · `duckdb` 패키지 설치)
