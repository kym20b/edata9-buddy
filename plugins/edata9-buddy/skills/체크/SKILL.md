# 체크 — 체크아웃 전 구조 점검

받은 인자: $ARGUMENTS

## 0. 이 점검의 성격 (반드시 지킬 것)

**«구조»만 본다. «내용의 질»은 판단하지 않는다.**

| 확인한다 | 확인하지 않는다 |
|---|---|
| 파일 · 폴더가 있는가 | 그 안의 판단이 옳은가 |
| 요구한 칸이 채워져 있는가 | 문장이 잘 쓰였는가 |
| 최소 개수를 채웠는가 | 그 기준이 좋은 기준인가 |

- 내용 검토가 필요해 보이면 결과 아래 «한 번 더 봐도 좋을 것»에 **언급만** 하고 판정에 넣지 않는다.
- **이름은 느슨하게 본다.** 폴더 · 파일 이름이 조금 달라도 같은 역할이면 통과다. 역할 자체가 없을 때만 «미흡».
- 볼 수 없는 것(폰에서 열리는가, 노션 페이지 — 노션이 이어져 있지 않을 때, 배포 서비스의 설정)은 «미흡»이 아니라 **«확인 불가 — 캡처로 확인»** 이다.
- **아무 파일도 만들거나 고치지 않는다.** 고치라고 해도 이 점검 안에서는 고치지 않는다.

## 1. 회차를 정한다

인자가 `W숫자-요일` 이면 그것. 비어 있으면 `${CLAUDE_PLUGIN_ROOT}/일정.json` 과 지금 날짜로 찾는다. 못 찾으면 묻고 멈춘다.

## 2. 작업 폴더를 찾는다

1. 지금 폴더가 `edata9-work` 이거나 그 아래면, 거기서 위로 올라가 `edata9-work` 를 찾는다.
2. 아니면 `C:\edata9-work` (윈도우) 또는 `~/edata9-work` 를 본다.
3. 그래도 없으면 **추측하지 말고** 작업 폴더 경로를 물어본 뒤 멈춘다.

## 3. 기준을 읽고 점검한다

`${CLAUDE_PLUGIN_ROOT}/기준/<회차>.md` 의 «점검 항목» 표를 한 줄씩 본다. 표에 없는 것은 보지 않는다. 없는 회차면 «아직 준비되지 않은 회차입니다» 라고 말하고 멈춘다.

git 저장소인지, 커밋이 있는지, 원격이 어디인지는 `git -C <폴더> log --oneline -3` · `git -C <폴더> remote -v` 처럼 **읽기만 하는 명령**으로 본다.

## 4. 이 모양으로만 보여 준다

```
[W○-○] 체크 — 통과 ○ · 미흡 ○ · 확인 불가 ○

| 항목 | 결과 | 근거 |
|---|---|---|
| … | 통과 / 미흡 / 확인 불가 | 찾은 파일 · 찾지 못한 것 |

오늘 남길 캡처 → (기준 파일의 «체크아웃 캡처») — 내 폴더에 저장해 두면 포트폴리오에 씁니다

미흡이 있다면 가장 빠른 길: (기준 파일의 «미흡일 때»)
```

미흡이 하나도 없으면 «기본 단계 완료입니다» 한 줄을 붙인다. 등급이나 점수를 매기지 않는다.
